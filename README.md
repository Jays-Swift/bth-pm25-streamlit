# 京津冀 PM2.5 预测与气象贡献研究

该目录为交互式研究界面的轻量运行目录，用于展示京津冀 PM2.5 浓度预测与气象贡献度分析项目。界面内嵌训练后的 LightGBM 模型和统一旗舰模型对象；预测台以 `flagship_pm25_meteorology_attribution.joblib` 作为主入口，选择城市、日期和小时后输入气象条件即可输出 PM2.5 预测结果，并呈现模型指标、SHAP 解释贡献、疫情分时期对比、气象背景图和化学组分机制诊断。

本界面定位为阶段性研究成果展示：一方面检验机器学习模型对城市小时尺度 PM2.5 的预测能力，另一方面通过严格控制变量准入的 weather-only 模型讨论气象背景对污染浓度变化的模型解释贡献。化学组分模块用于补充 O3、NO2、SO2、CO 等前体物对 sulfate、nitrate、ammonium、SNA 和碳质组分的机制诊断。相关结论应表述为阶段性研究判断和模型解释证据，不等同于严格因果效应。

## 研究数据

研究区域：京津冀 13 个城市。

数据时间：2018-01-01 00:00 至 2026-05-31 18:00。

样本规模：958,711 条 city-hour 记录。

PM2.5 缺失率：0%。

ERA5 PBLH 缺失率：0%。

时期划分：疫情前 2018-2019、疫情期 2020-2022、疫情后 2023+。2018-2022 PM2.5 使用 CNEMC/quotsoft 城市小时空气质量数据；2023 年以后使用此前整合的数据源。跨时期解释时应说明该数据源差异。

化学组分诊断使用 CAMS-EAC4 同源再分析数据，覆盖 2018-01-01 08:00:00 至 2024-11-01 05:00:00，约 77.9 万行 city-hour 样本。该数据层用于机制辅助，不应写成完整覆盖 2018-2026 的组分观测结论。

## 界面内容

预测台：选择城市、日期和小时，输入温度、湿度、风速、风向、气压、PBLH、逆温等气象变量，确认后由旗舰主模型输出当前小时 PM2.5 预测结果。旗舰对象内部按日期自动路由疫情前 log1p(PM2.5)、疫情期 PM2.5 原值和疫情后气候态异常代表模型，并呈现城市历史 PM2.5/PBLH、季节参考、风场和当天气象变量剖面。

化学组分机制诊断：预测台同步调用旗舰模型的 `predict_chemical_frame()`，输出 sulfate、nitrate、ammonium、SNA、SNA 占比、black carbon、organic matter、secondary fraction 和 nitrate/sulfate ratio。O3、NO2、SO2、CO 默认来自城市-月份-小时画像；如果用户有自己的前体物数据，可以开启自定义输入并覆盖默认值。

模型介绍：说明全时期高精度模型、分时期高精度模型、基础气象归因模型、过程型气象贡献模型、旗舰主模型和化学组分机制诊断头的指标、用途、特征口径、SHAP 贡献、残差结果和解释边界。

训练策略：按高精度预测模型、基础气象归因模型、过程型气象贡献模型和化学组分机制诊断模型分别说明变量准入、时间切分、特征生成、LightGBM/Optuna 调参、目标变量选择和评估口径。

研究验证：呈现留城市验证、组合外推验证、特征组消融、透明样条对照、天气型机制、SHAP 稳定性和典型气象条件误差。

## 代表模型指标

本轮重训范围需要单独说明：重训对象为过程型气象贡献模型 v2-core，即疫情前、疫情期、疫情后 3 个时期分别训练 PM2.5 原值、log1p(PM2.5)、同城同月同小时气候态异常 3 种目标形式，共 9 套候选模型；每套候选模型均使用 60 轮 Optuna trial。高精度预测模型、基础气象归因模型和 24 小时辅助预测模型为既有基准或方法对照，不属于本轮重训对象。

| 模型 | 训练口径 | 测试 MAE | 测试 RMSE | 测试 R2 |
|---|---|---:|---:|---:|
| 全时期高精度预测模型 | 2018+ extended | 7.72 | 12.06 | 0.917 |
| 疫情前高精度预测模型 | 2018-2019 extended | 2.27 | 3.60 | 0.993 |
| 疫情期高精度预测模型 | 2020-2022 extended | 1.77 | 3.09 | 0.993 |
| 疫情后高精度预测模型 | 2023+ extended | 1.33 | 2.59 | 0.997 |
| 疫情前过程型气象贡献模型 | 2018-2019 weather-only, log1p(PM2.5) | 19.62 | 28.24 | 0.544 |
| 疫情期过程型气象贡献模型 | 2020-2022 weather-only, PM2.5 原值 | 13.38 | 21.58 | 0.669 |
| 疫情后过程型气象贡献模型 | 2023+ weather-only, 气候态异常 | 17.43 | 24.78 | 0.737 |

高精度模型用于预测能力评估；过程型气象贡献模型严格保持 weather-only 变量准入原则，更适合支撑大气扩散条件与污染浓度变化关系的研究讨论。部署页面采用的过程型研究代表模型为疫情前 log1p(PM2.5)、疫情期 PM2.5 原值、疫情后同城同月同小时气候态异常；代表模型选择兼顾测试指标和解释口径，不仅按最高 R2 机械筛选。

当前预测台把上述三个代表模型封装为单一旗舰主模型：

| 入口 | 文件 | 用途 |
|---|---|---|
| PM2.5 主预测 | `models/flagship_pm25_meteorology_attribution.joblib` | `predict_frame()` 按日期路由三时期代表模型。 |
| 化学机制诊断 | 同一 flagship joblib | `predict_chemical_frame()` 输出 9 个化学组分目标。 |
| 构建脚本 | `scripts/build_flagship_pm25_meteorology_model.py` | 在完整项目目录中刷新旗舰模型对象。 |

化学机制诊断头采用 CAMS-EAC4 主数据集训练，默认使用 precursor 口径，即 weather-only + O3/NO2/SO2/CO。sulfate、nitrate、ammonium、SNA 和 secondary fraction 对前体物信息有明确增益；black carbon 与 organic matter 更适合作为共排放/共变化信号；nitrate/sulfate ratio 测试表现较弱，界面中仅作为敏感性诊断。

SHAP、残差、响应曲线、组合外推验证和特征组消融主要用于说明模型在给定特征空间和验证设计下如何使用气象信息。跨时期比较尤其需要同时说明 2023+ PM2.5 数据源与 2018-2022 不完全一致、缺少直接排放清单约束，以及气候态异常目标对城市历史基准的依赖。

## 本地运行

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py --server.port 8520 --server.address 127.0.0.1
```

## 目录说明

```text
app/                 研究界面源码
app_assets/          指标、SHAP、城市画像和界面数据
models/              已训练模型对象
scripts/             旗舰模型类与部署辅助脚本
streamlit_app.py     运行入口
requirements.txt     运行依赖
```

完整原始数据和下载脚本不放入该轻量运行目录；研究界面运行只依赖模型对象和轻量数据资产。
